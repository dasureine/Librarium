# Librarium 内置 AI 学术工作台 · 方案定稿

> 本文是「Librarium 制书项目 + 内置 AI」的总体设计方案，作为后续分阶段开发的唯一依据。
> 改动本方案须先更新本文；阶段开发一律以本文为准。

## 0. 定位与目标

把现有 Librarium（拆书 → 精读笔记 → 知识地图）收编进一个更大的「AI 学术工作台」：

- 用户可按 **书 / 标签 / 章节（一份或几份）** 圈定语料范围；
- 内置 AI 在圈定范围内做 **单独思考**（单章/单书深读）或 **关联思考**（跨章/跨书/跨标签关联）；
- 回答用户问题、**激发学术灵感**；
- 内置 **外部信息源开关**（三档），并可选 **联网搜索**（可开可关）；
- 所有 AI 论断**可溯源**（点击跳回原文片段）；
- AI 产出的灵感、错题**回流**进语料库，形成越用越厚的闭环。

## 1. 总体架构（四层 + 回流闭环）

```

│    · 单独思考 / 关联思考         · 外源三档 + 联网子开关     │
```

## 2. 三轴解耦（范围 × 模式 × 外源）

### 2.1 范围（决定上下文从哪来）

- 多选：任意组合 书 / 标签（二级学科）/ 章节。
- 单独思考 = 小范围（1~2 章），整段精读注入。
- 关联思考 = 大范围（整书 / 多书 / 跨标签），走检索召回。

### 2.2 模式（决定 system 提示词与输出格式）

| 模式 | 职责 |
| :--- | :--- |
| 问答 | 就圈定语料回答问题，附依据 |
| 学术启发 | 主动提出研究问题、跨书关联、论证张力 |
| 闭卷考官 | 单题过关、严苛判分、只认语料、错题入错题本 |
| 逐字精读考官 | 先出「无遗漏细节台账」→ 逐条挖坑考核 → 结构回扣 |

### 2.3 外源三档 + 联网子开关

| 档位 | 语料外知识 | 联网搜索 |
| :--- | :--- | :--- |
| 闭卷 | 禁止；超纲答「原文未提及」 | 无 |
| 半开卷 | 允许模型通识做背景，强制标注「书外」 | 默认关，可开 |
| 全开卷 | 允许通识 + 联网，全部标注来源 | 默认关，可开 |

- 「联网搜索」是独立子开关（默认关），仅在「半开卷 / 全开卷」生效；闭卷时无视该开关。

## 3. 检索方案（结构化 + 全文，向量留作升级）

- 起步：**结构化索引 + 全文/关键词召回**，零外部依赖，纯本地（JSON / SQLite FTS）。
- 大范围：先全文粗筛 top-k，再按「章节 / 类型 / 页码」结构排序装配。
- 阶段 4（可选升级）：叠一层向量/语义检索做精排，解决「用词不同但意思相通」的跨书关联；与全文检索共存，不替代。

## 4. 定位锚点方案（解决页码问题）

**主锚点：`第X章 · 片段N`**（PDF / EPUB 通用，稳定、不依赖页码）。

- 拆分后，索引阶段把每章切成「片段」（段落或小切片），按顺序编号。
- 片段 ID：`{book_slug}:{chapter_index}:{segment_seq}`，点击跳转用片段 ID 定位。

**页码 = 可选元数据**：

| 格式 | 文件页 | 印刷页 |
| :--- | :--- | :--- |
| PDF | 保留（物理页，永远可算） | `印刷页 = 文件页 − page_offset`，offset 由用户填一次（扉页+序+目录页数）；极端情况用 `page_map` 手工映射 |
| EPUB | 无（fitz 合成页无意义） | 无 |

- `page_offset` / `page_map` 存于 `workspace/<slug>/book_meta.json`，**索引时事后套用，不重新拆书**。
- 引用展示统一：`第X章 · 片段N`（有印刷页时追加 `印刷页P`；PDF 至少标 `文件页Q`）。

## 5. 回流闭环

- AI 灵感 / 好问题 / 跨书关联 → `workspace/<书>/insights/`（可检索）。
- 闭卷考官错题 → `workspace/<书>/quiz_wrong_answers.md`。
- 二者进入语料索引，供后续「关联思考」检索。

## 6. 分阶段落地路线

- **阶段 0｜数据地基**：`scripts/build_corpus.py` + `data/corpus_index.json`（章节→片段切分、片段 ID、文件页/印刷页、类型元数据）；`book_meta.json` 支持 `page_offset`。
- **阶段 1｜内置 AI 核心**：`/api/chat`（SSE 流式）+ 上下文装配器（范围×模式×外源三档+联网子开关）+ 引用溯源。
- **阶段 2｜前端工作台**：聊天抽屉 + 书/标签/章节多选器 + 模式切换 + 外源三档，沿用深雾灰绿视觉。
- **阶段 3｜回流 + 考官**：闭卷/逐字考官作为内置「模式」上线，错题本、灵感本落盘，洞见回流索引。
- **阶段 4（可选）**：向量/语义检索升级、跨书关联关系图可视化。

## 7. 硬性红线（沿用项目规范，冲突处按本节执行）

- 严禁修改 `notes/*.md`（用户只读原稿）。
- 严禁修改 `books.json` 中的书目数据、既有 `maps/` 地图、`templates/map-template.html`。
- 阶段 2 会新增/改造 `index.html` 与 `server.py`（现有红线里这两者受保护）：**动它们之前须单独征得用户确认**，且只做「新增聊天工作台入口 / 新增 API 命名空间」的加法改造，不改动既有制书流程与既有视觉。

## 8. 待确认与风险

- 联网搜索的接入方式（搜索 API 选型、成本）在阶段 2 前单独确认。
- 「逐字无死角」为尽力而为：靠小切片 + 先出「无遗漏台账」人肉核对逼近，不做 100% 不漏的承诺。
